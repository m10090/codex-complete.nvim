1. Introduction                                 *codex-complete-introduction*

codex-complete.nvim offers completion suggestions generated by the locally
installed Codex CLI in the completion menu, through null-ls (none-ls.nvim). It reuses ChatGPT authentication established by
`codex login`; no API key is accepted or stored by the plugin.

Requirements: Neovim 0.10+, Codex CLI, and ChatGPT subscription access to
Codex. Run `:checkhealth codex_complete` to verify the environment.
none-ls.nvim and an LSP completion client such as nvim-cmp with cmp-nvim-lsp
are needed to show suggestions in the completion menu.

2. Setup                                               *codex-complete-setup*

Call setup once from your Neovim configuration: >lua

  require("codex_complete").setup()
<
The default insert-mode mappings are:

  <M-;>      Accept a suggestion.
  <M-s>      Request a suggestion manually.

The default normal-mode mappings are:

  <leader>ac  Generate code from the comment under the cursor.
  <M-;>       Accept a comment replacement.
  <leader>at  Toggle suggestions.
  <leader>am  Select the completion model.
  <leader>ar  Select the reasoning level.

Continuing to type or leaving insert mode dismisses a visible suggestion. The
CodexCompleteDismiss command and dismiss() Lua function remain available for
explicit dismissal.

No loading indicator is drawn by default. Set loading_indicator to true in
setup() to show an inline spinner while Codex generates a suggestion.

Suggestion text uses CodexCompleteSuggestion with
CodexCompleteSuggestionBackground for black text on a dark green (#50A14F)
background applied only behind the ghost text. Override these groups with
highlights.suggestion and highlights.background. Set highlights.background to
false for text without a background.

When a multiline preview repositions an existing auto-paired closing
delimiter, that delimiter uses MatchParen so it remains visually distinct from
generated text. Override this group with highlights.existing_delimiter.

The most recent suggestion is cached in memory per buffer. Returning to its
original context restores it without a request. Typing a matching prefix shows
only the remaining text. Accepting or explicitly dismissing it clears the
buffer's cached suggestion. Fully typing it does not request another completion
until additional text stops matching and the debounce period elapses.

After accepting a suggestion, automatic completion waits for the next
insert-mode edit. Moving the cursor alone does not start another request;
manual requests remain available immediately.

Auto-paired closing parentheses, brackets, and braces are treated as part of
the cached completion. Typing an opening delimiter shows the full remaining
suggestion around the existing closer without starting a request.

Every setup option and its default is documented in the project README.
Mappings can be replaced with strings or disabled with `false`.

Related context combines LSP definitions, matching project buffers, and bounded
rg searches. Unsaved buffers override disk contents. context.related defaults to:
>lua
  { enabled = true, timeout_ms = 150, max_bytes = 16 * 1024, max_snippets = 8 }
<
This budget supplements the current-buffer budget. Cached sources are checked
for changes before reuse. Missing LSP support or rg is handled gracefully.
Codex threads start in the active file's directory. Inline completions do not
read files or skills unless codex.completion_tools is true; comment
replacements may. See |codex-complete-context|.

status().engine.context reports duration_ms, cache_hits, and source filenames.
status().engine.duration_ms reports the last request's total duration.

Place the cursor on a comment and press <leader>ac to generate a replacement,
or run :CodexCompleteComment. The full Tree-sitter comment node is sent as the
instruction, and highlighted replacement text is previewed below the comment
without changing the buffer. Press normal-mode <M-;> to replace the comment.
Moving the cursor or editing the buffer invalidates the preview.

This action requires a Tree-sitter parser for the current buffer. It warns and
does not send a request when no parser is available or the cursor is not over a
comment. Comment replacements are explicit only and are not added to the
automatic-completion cache. Configure the mappings with
keymaps.comment_trigger and keymaps.comment_accept.

The built-in defaults use gpt-6-luna with low reasoning. Set codex.model or
codex.effort to override either value. Runtime selections last for the current
Neovim session and are reset whenever setup() runs again.

Set codex.effort to the default reasoning effort. Runtime effort selections
are validated against the active model. If a model switch makes the current
effort incompatible, the model's advertised default effort is selected. Model
and effort changes cancel and clear older suggestions.

3. Commands                                         *codex-complete-commands*

                                                    *:CodexComplete*
:CodexComplete              Request a completion immediately.

                                                    *:CodexCompleteComment*
:CodexCompleteComment       Generate code from the Tree-sitter comment under
                            the cursor. The Lua function is trigger_comment().

                                                    *:CodexCompleteEnable*
:CodexCompleteEnable        Enable completion requests.

                                                    *:CodexCompleteDisable*
:CodexCompleteDisable       Disable requests and cancel current work.

                                                    *:CodexCompleteToggle*
:CodexCompleteToggle        Toggle completion requests.

                                                    *:CodexCompleteDismiss*
:CodexCompleteDismiss       Clear the current suggestion.

                                                    *:CodexCompleteModel*
:CodexCompleteModel         Select from the visible Codex model catalog.
:CodexCompleteModel {id}    Validate and select a model ID.
:CodexCompleteModel!        Restore the configured default model.

The corresponding Lua functions are select_model(), set_model(id), and
reset_model(). list_models(callback) asynchronously returns the visible model
catalog as callback(error, models). status().model contains current and
default fields.

                                                    *:CodexCompleteEffort*
:CodexCompleteEffort        Select an effort supported by the active model.
:CodexCompleteEffort {level} Validate and select a reasoning effort.
:CodexCompleteEffort!       Restore the configured default effort when the
                            active model supports it.

The corresponding Lua functions are select_effort(), set_effort(level), and
reset_effort(). list_efforts(callback) asynchronously returns the active
model's advertised effort options. status().effort contains current and
default fields.

4. Completion menu                                   *codex-complete-null-ls*

setup() registers a codex_complete completion source with null-ls when it is
installed. null-ls acts as a language server, so the suggestion appears in any
LSP completion client, such as nvim-cmp with cmp-nvim-lsp. No extra source
entry is needed.

The entry replaces the keyword being typed with the full suggestion. The
source does not start requests itself; it answers once the automatic or manual
request finishes, and other null-ls completion sources wait for it meanwhile.

Inline ghost text is off by default. Set ghost_text to true in setup() to draw
the suggestion at the cursor as well. The accept mapping works either way.

5. Speed and context                                 *codex-complete-context*

Inline completions are answered in a single model response: Codex is told not
to read files or load skills. Comment replacements may still do both. Set
codex.completion_tools to true to allow reads for inline completions.

With codex.prewarm enabled, the app server and the next completion thread are
started on entering insert mode and after each request.

Before each inline request the plugin collects signature help, the completion
list for the typed word, hover text for identifiers earlier on the line, and
nearby diagnostics from attached language servers, within
context.lsp.timeout_ms. Set context.lsp.enabled to false to skip this.

A rolling window of recent edits (context.activity) is sent as unified diffs
with the names of recently visited files. After intent.idle_ms without edits
and at least intent.min_edits new edits, a background request summarises what
you are working on; later requests include the summary.

The first time a file inside a Git repository is opened, one background
request lets Codex read the project and write a brief of its purpose, layout,
main modules, and conventions. The brief is cached on disk, sent with every
completion, and rewritten after project_brief.max_age_days. Set
project_brief.enabled to false to disable it.

                                                       *:CodexCompleteProject*
:CodexCompleteProject[!]    Show the cached project brief; with ! rewrite it.
                            The Lua function is project_brief(refresh).

                                                        *:CodexCompleteIntent*
:CodexCompleteIntent        Show the current intent summary. The Lua function
                            is intent(). Summaries count against your Codex
                            limits; set intent.enabled to false to disable.

==============================================================================
6. Privacy                                           *codex-complete-privacy*

Requests include bounded current-buffer text and related project snippets with
filenames and line ranges. They also include language-server text for the
cursor, diffs of recent edits, and names of recently visited files. Background
intent summaries send the same diffs and file names. Comment requests include the comment and its range.
Local retrieval excludes sensitive filenames and generated directories; disk
searches respect ignore rules. Codex may also read project files, skills, and
references independently of those filters. Threads are ephemeral with read-only
sandboxing, network access disabled, and approvals disabled. Codex is instructed
to produce only the requested edit and not modify files or run skill scripts.
